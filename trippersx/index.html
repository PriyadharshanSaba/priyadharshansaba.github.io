How it works

From a five-line brief to a page the group can play with

Planning a trip well takes hours of tabs: prices, opening times, drive times, photos and backup options. The agents do that legwork. I check it, book it and talk to the client.

01 · Brief

Tell it the trip

Place, dates, travellers, budget and up to three mood words, like honeymoon, relax, scuba or boys trip, adventures, car drive.

02 · Plan

Agent 1 researches and plans

Live prices, opening hours and drive times, turned into a day-by-day plan with a cheaper and a similar option for the big items.

03 · Earn

Agent 2 works out my cut

Card cashback and agent rates, row by row. Plain code, no AI, and it stays private.

04 · Publish

Agent 3 makes the page

Strips every private field, checks nothing leaked, and publishes the trip page the client opens and rearranges.

Who does what

The agents do the legwork. The business stays mine.

The split is deliberate: everything repeatable goes to the agents, and everything that needs judgement, trust or a signature stays with a person.

The agents handle

  • Researching prices, opening hours and drive times
  • Building a day-by-day plan inside the budget
  • Offering a cheaper and a similar option for big items
  • Writing short, mood-matched descriptions and finding photos
  • Working out card cashback and agent-rate earnings per booking
  • Publishing a clean page with no private numbers on it

I handle

  • Commercial calls: which offers to chase, what to charge
  • Talking to clients and to hotels and operators for agent rates
  • Checking the plan, and every price before paying
  • Booking, paying and keeping receipts
  • Being the person they call when something goes wrong

Read it like a trip

One row per part of the day, one card per thing to do

Each day leads with the place, then morning, afternoon, evening and night. Every plan item is a square photo card with a short verb-first title.

  • Titles like "Sunset at Anjaneya Hill", not paragraphs
  • Price per person on every card
  • Hotels and drives marked Fixed so nobody drags them by accident
  • Cheaper and similar choices wait in a dashed Options box

Rearrange without breaking it

Drag things around. The plan still has to be possible.

Every event knows its safe time window: opening hours, the drive from the hotel and how long people usually spend there. So the page knows the sloth bear sanctuary only works on an afternoon and needs about four hours.

  • Times it can't happen fade out while you drag, with the reason

Under the hood · for developers

Three agents, one contract, and a person in the loop

The system is a Next.js app on Vercel. The agents never talk to each other directly. They read and write one itinerary workbook in a fixed, versioned format, so every step can be checked, replayed, or opened in Excel by a human.

Contract first

A workbook, not a chat log

Every agent reads and writes the same versioned format, found by anchor text, not row numbers. Validation runs after every step: headers, alternatives, totals, dates. Breaking changes get a new version.

Token budget

Cheap model searches, strong model plans

Web results only go to the small research model, which saves a short price list cached for 7 days per destination, month and mood. The planner never sees raw search results.

Fix, don't re-ask

Mechanical slips fixed in code

Day order, labels and duplicate dates are repaired in code. Only real planning errors (over budget, wrong dates, a slot that can't fit) go back to the model, because each redo rewrites the whole plan.

No AI where it isn't needed

Earnings are plain arithmetic

Agent 2 is ordinary code over a card and route config: cashback minus forex markup plus any agent rate. It reports a sure lower end and an upside, and drops anything under ₹300.

Privacy gate

Nothing private gets published

Agent 3 strips the earnings columns and private summary rows, then scans the result for earnings wording and refuses to publish if anything slipped through.

Rules engine

Time windows as pure functions

The drag-and-drop page runs on two small functions, check and simulate, with unit tests written from the real trip. The same rules validate the planner's output.

// Can this card go into this day and time slot?
function check(card, slot) {
  if (card.locked && slot !== card.home)
    return no(`Fixed to ${label(card.home)}`);
  if (overlap(slot) === 0)
    return no("You're on the road then");
  if (!card.canHappenIn.includes(slot.code))
    return no(`Not in the ${slot.word} · ${card.openHours}`);
  if (card.needsHrs > free(slot, { without: card }))
    return no(`Needs ${card.needsHrs} h · ${free(slot)} h free here`);
  return ok();
}

// free = (slot window ∩ hours at the destination)
//        − fixed items already in that slot
How I build it

I direct the agents that write the code, too

I rarely hand-write code now. I work as the product owner and reviewer: design with Claude on a canvas, turn the decisions into a written spec, and hand that to Claude Code to build in reviewed phases.

  • Mockups built on the real trip data, not lorem ipsum
  • A handoff spec with the contract, rules and expected test results
  • Claude Code shows a plan first, then builds one phase per commit
  • I review each phase against the spec and the live mockup
Idea→Claude · design canvas→Spec + test data→Claude Code · phased build→My review→Vercel
Trust

Estimates the client can rely on

A plan that looks finished but isn't bookable is worse than no plan. A few rules keep it honest.

Every price is a checked estimate

Prices come from live research with sources, and the page says so. I check each booking page before paying. One review caught a ₹9,000 car rental missing from a total, which is exactly why a person signs off.

Possible, not just pretty

Opening hours, drive times and realistic durations mean the day actually fits. Wildlife after dark or a climb in the midday heat simply can't be scheduled.

My earnings stay on my side

Cashback and agent rates are worked out for me and never shown to the client. They pay the public price; what I earn comes from cards and operators, not from padding their plan.
